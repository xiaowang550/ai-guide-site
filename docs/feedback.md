# 问题反馈与邮件通知

公开入口 `/feedback/` 无需账号，支持文字、选填邮箱和最多 3 张截图。顶栏入口会带入当前页面，页脚和手机菜单也能进入。

截图在浏览器重新编码（清除原图元数据）、缩放与压缩，每张不超过 300 KB，原始 PNG/JPG/WebP 不超过 5 MB。服务端限长读取请求、核对图片签名并使用生成的文件名。D1 保存截图；读取接口 `/api/admin/feedback-assets/:id` 必须有 owner 会话，禁止缓存。联系方式与图片不公开。

后台“用户反馈”包含处理状态、备注、私有截图和邮件通知状态。“暂不采纳”保留记录。评估方向：符合使用规范、方便、快捷、易理解；不承诺采纳所有建议。

## 首次配置邮件

1. 用 **1987215931@qq.com** 注册 [Resend](https://resend.com/)，创建 Sending access API Key。使用其共享测试地址 `onboarding@resend.dev` 时，只能发给账号自己的邮箱；或设置并验证自有发信域名。
2. 管理后台 → 用户反馈 → 邮件通知设置，填写发件地址和 Key。Key 使用现有服务端 `AI_CREDENTIALS_KEY` 派生独立 AES-GCM 密钥加密，不修改助手已有密钥，不返回明文。
3. 点击“发送测试邮件”。接口成功表示邮件服务接收；以邮箱实际收到为准，也检查垃圾邮件。
4. 点击“补发待发送通知”，每次最多 5 条。新反馈会自动通知，并尝试补发到期的失败记录；没有新访问时可在后台手动补发。

收件人固定为 **1987215931@qq.com**，访客输入的联系邮箱不会作为发信对象。邮件包含文字、页面、反馈编号与截图附件。未配置或发送失败时仍保留反馈，前台只确认收到反馈，不声称邮件送达。

API 可选注入 `RESEND_API_KEY` / `FEEDBACK_FROM`（Cloudflare Secret / 配置变量）；通常直接在后台填写即可。原始供应商错误与 Key 不写入审计日志，使用无敏感信息的错误提示。发信使用固定 HTTPS 供应商端点，禁止重定向与自定义 URL。

反馈与附件、通知排队在同一数据库事务中提交。客户端提交编号避免网络重试重复建单；通知使用数据库租约及 Resend Idempotency-Key 避免并发重复发送（供应商幂等窗口 24 小时）。[发送邮件 API](https://resend.com/docs/api-reference/emails/send-email)。
