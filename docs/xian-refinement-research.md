# XIAN 视觉与交互打磨研究

研究日期：2026-10-30。用途：延续弦域 XIAN 的科幻方向，改善空间质感、浏览节奏和操作反馈。本文区分来源事实与设计建议；获奖记录仅属于相应参考网站。

## 结论

XIAN 应把「一个有质感的主场景」与「可看懂、可直接操作的产品流程」结合起来。首屏负责让人记住品牌，任务预览和工作台负责让人知道下一步。优先改善构图、材质层次和状态衔接，再增加有明确作用的动效。

针对现有上线截图的判断：主标题已有辨识度，青柠与墨黑方向可保留；右侧轨道球各线条亮度接近，前后层次不足；首屏的小字号技术标签偏多。后续栏目应采用不同密度与比例，避免工具、学习、案例都呈现同一套卡片节奏。以上属于本项目的设计判断，不是参考站的原话。

## 获奖站与产品站

### Lusion：让一个场景形成整页记忆

[Awwwards 官方年度目录](https://www.awwwards.com/websites/sites_of_the_year/)列出 Lusion v3 为 2023 年度网站；[Lusion v3 官方评选页](https://www.awwwards.com/sites/lusion-v3)列有响应式光标和滚动动画等亮点。该记录针对历史版本，不能直接当作 2026 年当前页面每项细节的证明。

[Lusion 当前官网](https://lusion.co/)用一段总叙事进入精选作品，再收束到联系入口。可借鉴的是统一的场景气质、明显的内容尺度变化和少量主要行动。XIAN 可在主视觉、案例大图和页尾轨道之间保持同一组形态语言，不需要把全站改成 3D 展厅。

### Igloo Inc：交互随内容变化，避免重复

[Awwwards 官方年度目录](https://www.awwwards.com/websites/sites_of_the_year/)列出 Igloo Inc 为 2024 年度网站。[Awwwards 发布的官方制作案例](https://www.awwwards.com/igloo-inc-case-study.html)说明：团队先用草图和简易动画规划用户路径；不同项目采用不同冰块外形，避免滚动时过于相似；制作过程中持续检查低端设备表现；链接区的粒子形态跟随选中的链接改变。

适合 XIAN 的不是冰雪材质，而是「内容改变时，画面也有合理变化」。会议纪要可显示由散点汇聚成行动清单的结构；文案任务显示文字条目；工作流显示连接节点。案例也应各有自己的成果预览，不再依靠同样的装饰图标区分。

### Linear：用可读的操作过程解释产品

[Linear 官网](https://linear.app/)以真实界面形式展示任务活动、收集、规划、代理协作与交付等流程；内容组织有清晰的工作顺序。此处作为产品设计参考，不对其获奖情况作任何声明。

XIAN 应把「试一试」做成一个完整的小过程：选任务 → 看示例材料 → 修改要求 → 运行模型 → 看结果 → 复制或继续修改。预览内容明确标为「示例」，真实生成与示例预览采用不同状态。不要导入其他产品的客户标志、统计数字或能力承诺。

## 建议实施顺序

### 1. 首屏：从平面线球变成有前后层次的轨道装置

- 保留 XIAN 标志与青柠主色。降低背景网格和外围轨迹对比，把最亮的线集中在前景 2–3 条路径与一个中心亮点。
- 加入明确的背面衰减、中心体积、微弱环境光和边缘遮挡；用有限层次表现深度，避免单靠多画粒子。
- 主要标题和按钮在 HTML 中立即可读。场景慢速进入只发生一次，用户无需等动画结束才能开始。
- 三个中文任务选择与场景对应。激活后改变形态并更新旁边的材料／结果预览；指针离开后平滑回正。
- 移动端采用固定构图与点击切换，保留暂停；不要求悬停、拖拽或精细命中。

### 2. 任务预览：让交互回答「这个网站能帮我做什么」

- 默认露出一份短材料及其对应结果。用户切换任务可立即理解差异，尚未接入模型时也能看懂功能。
- 「带入工作台」应保留当前选择和材料，不把用户带到空白输入框；输入内容有改动时避免被场景切换覆盖。
- 实际模型调用显示等待、生成、停止、错误、重试等真实状态。不要用伪造百分比或演示结果冒充生成成功。
- 结果区提供复制反馈、重新生成和继续修改；不把操作反馈只藏在短暂颜色变化里。

### 3. 页面节奏：改变比例与密度

- 首屏：大标题＋一个主装置，聚焦一个主要动作。
- 工具：保持可比较的紧凑网格，名称、用途、收藏、对比突出。
- 工作台：宽而清晰的工作区，文字与材料拥有足够空间。
- 学习：一列路径，展开只显示当前路径内容，附一条小型进度轨道。
- 案例：一个主案例展示实际成果，旁边配置较小的案例目录；点击切换成果预览。
- 动态：轻量时间列表，避免再次出现同规格的大卡片。
- 这些章节继续使用原有栏目权限和管理员排序；视觉联动不能假设任意相邻栏目永远存在。

### 4. 微交互统一

| 状态 | 建议表现 | 作用 |
| --- | --- | --- |
| 悬停／键盘聚焦 | 局部柔光、箭头短移、清晰焦点边缘 | 表达可操作对象 |
| 按下 | 轻微压下，立即出现响应 | 减少「没点上」的疑惑 |
| 加入收藏／对比 | 图标与文字都改变，出现可撤销反馈 | 让操作有持续结果 |
| 任务切换 | 场景与预览共同过渡，选中状态常驻 | 建立操作与结果的关系 |
| 复制完成 | 「已复制」短暂替换按钮文字 | 明确成功 |
| 模型等待 | 输入区保留、可停止、提示实际等待状态 | 避免误以为页面卡死 |

建议值：悬停约 160–220ms、任务切换约 400–650ms、首次场景进入约 700–900ms。这些是本项目拟定的起点，需按实现测试，不是对参考站动画的测量。

## 实现取舍与验收

- 优先继续使用现有 Canvas／SVG 与 CSS，不为了一个光效引入整套动画库。若采用组件库，确认其依赖体积、许可证和服务端渲染行为。
- 主场景采用渐进增强。Canvas 初始化失败、网络慢、减少动态效果开启时，标题、材料预览、按钮仍可用。
- 建议空闲时降低帧率，交互时短时提高；移动端限制像素比并降低粒子数量。离屏或标签页隐藏时停止绘制。数值需要在真机上验证。
- 动效不能改变浏览器的滚动逻辑，也不能让正常内容等待动画触发才显示。避免整页滚动劫持、自动音频和无退出方式的开场。
- 键盘可完成任务切换、搜索、收藏、对比和生成；触屏不依赖悬停；减少动态效果模式使用静态场景和淡入替代持续旋转。
- 至少检查 320px、390px、768px、1440px；Chromium 与 WebKit；模型断开、响应慢、失败、停止后重试；栏目隐藏、删除与管理员自定义替换。
- 不使用虚构的用户数、生成速度、成功率或奖励徽章来增加「高级感」。
